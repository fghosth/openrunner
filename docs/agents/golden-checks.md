# 金标准对照的纪律

> 「单元测试全绿证明不了公式对」——因为期望值也来自同一个理解，同一个误解会同时产生
> 实现和期望值。所以要另一份**独立**实现来对。而那份独立实现如果也是照抄来的，
> 对照就变成了自说自话。

本文记录这件事故、它的根因、以及现在用来防它的四道闸门。

## 事故：三处同错的 W'bal

W′balance 的公式有三个地方各写了一份：

1. `openrunner-core/wbal.go`（Go 实现）
2. `scripts/golden-check.py`（Python 参照，用来「独立验证」Go）
3. `wbal_test.go` 里那个名字叫「独立真值」的 `naive()`

三份都写成：

```
I += e^(t/τ) · (P−CP)⁺ · Δt        # 前向积分
W'bal = W' − e^(−t/τ) · I          # 再乘衰减
```

这在数学上等价于 `dW′bal/dt = −(P−CP) + (W′−W′bal)/τ` —— **超临界段也带回充项**。
后果：储备只趋近 `W′ − τ·(P−CP)`，持续小幅超 CP 时永不耗竭。

实测（CP=250 W、W′=20 kJ、τ=316 s、恒定 CP+20 W）：1000 秒后仍剩 **13936 J**，
按 Skiba 2012 的分段模型应为 **0**。

而 `make golden-check` 当时显示：

```
[5] W'bal（Skiba 2012 积分式独立实现 vs Go，1 条骑行流 / 126 采样点）
      最大绝对差 0.000e+00 ✓
```

`0.000e+00` —— 因为两边逐字相同。**对照台越是完美对齐，越说明它没在验证任何东西。**

### 这份错误公式是从哪来的

从 GoldenCheetah 的 `GC_WBALFORM=int`（`WPrime.cpp` 的 `WPrimeIntegrator::run`）。
那是 GC 为了省 CPU 引入的**近似**：把 O(n²) 的回看积分压成 O(n) 的前向累加。近似本身
在「大幅超 CP 迅速耗尽」的场景下无害（储备早被钳到 0），所以 GC 用它是合理的工程取舍。

但我们把「某个开源实现的性能优化」当成了「论文里的公式」抄下来，还给它贴了
「Skiba 2012 积分式」的引用。同一份 `WPrime.cpp` 里就有分段式的正确实现
（`minForCP`：超 CP 扣减、低于 CP 按剩余比例回充），我们抄错了那一段。

## 同一次事故暴露的另外三个问题

### 1. 同一个公式在一个文件里有两份

`golden-check.py` 里 W′bal 出现两次（真实流段 + 合成用例段）。修好第一份之后，
合成用例段立刻爆 `最大差 3.057e+01`。**修一处等于没修。**

更隐蔽的是第二处还顺手把用例显式给的 `tau=300` 用 `tau_from_data(...)=561` 覆盖了。
积分式下这个错误几乎不敏感（储备早就 0 了），分段式下直接露馅。

### 2. 验证脚本会悄悄脱队

`TestGoldenDumpRtss` 的 docstring 写着「走生产口径」，实际用的是
`core.NormalizedSpeedKph`（裸 4 次方均值）。rTSS 改成 30 秒平滑之后，这个 dump
还留在旧函数上 —— 于是 Go dump 和 Python 参照同为「裸」口径，**逐值一致地一起错**。

没有任何东西会报错：dump 顺利写出，对照顺利通过，只是两边都测的不是生产代码。

### 3. 「独立真值」是抄的

`wbal_test.go` 里那个函数叫 `naive`，注释写着「朴素定义（04 文档原文语义）」。
它不是从论文推的，是从文档里那段（错的）公式转写的。取了个「独立」的名字，
做着和实现一模一样的事。

## 现在的四道闸门

### 闸门 1：参照只有一份，且在 `scripts/goldenlib.py`

`golden-check.py` 只做「取数 → 调参照 → 比 → 报告」，所有公式集中在 `goldenlib.py`。
结构上消灭「同公式两份」这个失败模式。

每个函数的 docstring 必须写清「这一行来自论文/定义的哪一句」，
以及**与 Go 的有意偏离**（前导窗口、停表样本等）。

### 闸门 2：`make ref-test` 用解析真值钉住参照自己

`scripts/test_golden_refs.py`，42 条断言，纯 python 标准库，秒级，不 import Go 任何东西。
每一条只依赖论文/定义里的数学性质：

| 类型 | 例子 |
|---|---|
| 解析解 | 恒定 ΔP 时储备在 `W′/ΔP` 秒整点归零；恢复段 `W′ − (W′−W'bal₀)·e^(−Δt/τ)`；指数衰减 `s·(1−aⁿ)` |
| 定义锚点 | 阈值强度 1 小时 = **100 分**（TRIMP100 与 rTSS 各一条）；IF 加倍 → 4 倍 |
| 数学恒等式 | 4 次幂平均 ≥ 算术平均；一阶低通阶跃响应不过冲；钳位边界 |
| 真值回收 | 合成点必须精确还原 CS/D′、Banister 的 p0/k1/k2 |
| 守卫 | 分母无定义 → 0；零值不产生负荷 |
| 约定显式化 | 同一序列在 skip / zeropad 两种前导约定下的差值方向与量级 |

验算这批断言的有效性：把参照的 W′bal 改回积分式 → 4 条立刻红；
把参照的 rTSS 改回裸 NS → 对照台 214 条全超容忍。**两级都能抓红。**

### 闸门 3：dump 必须走生产函数，并用合成库硬保证

- dump 测试调用**生产函数本身**（`core.NormalizedSpeed`、`core.WBal`、`ComputePMC`），
  不重新拼一遍算式。
- `TestGoldenDumpRtssMatchesProductionMetrics`：在合成库上跑 `recomputeMetrics`
  （真正的落库路径），断言 dump 的算式与库里的 `rtss` 逐值相等；再反向断言 dump
  用的是平滑口径而不是裸 4 次方均值。
- 与历史快照里的持久化值只做**软提示**（快照可能早于代码变更），不硬失败 ——
  否则「因为旧快照而红」会逼着人放宽检查。

### 闸门 4：CI + `make test`

`make test` 与 CI 的 `reference` job 都先跑 `test_golden_refs.py`。
`make golden-check` 也依赖 `ref-test`：参照错了，对照出来的「一致」没有意义。

## 已知偏离，用数字说话

参照与 Go 的偏离必须**量出来并写进文档**，不能用容差糊过去：

| 偏离 | 性质 | 实测 |
|---|---|---|
| NP/rTSS 的前导窗口 | openrunner 选 skip（未满窗口不参与），GoldenCheetah 零补齐 | 中位 0.21%、p90 1.40%、最大 11.66%（短流）；214 条里 213 条 skip ≥ zeropad，唯一反向的是起始段带高伪影的活动（skip 反而更保守） |
| 单课分析用原始速度 | `analyze_session.py` 用 NGP（坡度修正），openrunner 直接吃速度流 | 见下（已量化） |
| TRIMPzonal 低区 | openrunner 不计 <64% MaxHR（跟 GC 的 `time_in_zone_H*` 口径），早期版本记进 zone1 | 1 小时 <64% MaxHR：0 分 vs 50 分 |

### 单课分析的坡度修正（2026-11 量化）

`analyze_session.py` 用 NGP（坡度修正配速），openrunner 用原始速度——流里**有**海拔通道
（`Stream.AltitudeM`），所以不是「没法算」，而是「算不算」的取舍。用 Minetti 2002 的跑步
能量代价式（GAP）在同一批活动上重算解耦，对比结果：

| 指标 | 值 |
|---|---|
| 可比活动（≥60 min 且有心率/速度） | 192 条 |
| \|GAP − 原始\| 中位 | 0.21 个百分点 |
| p90 | 0.82 个百分点 |
| 最大 | 26.76 个百分点（活动 88，仅 22 m 爬升 → 是高度通道噪声不是真坡度） |
| 跨过 5% 判定线（ok ↔ moderate/large） | 5 / 192 |
| 样本爬升分布 | 中位 9 m，p90 34 m，最大 93 m |

结论：**这个用户的库全是平路跑**，坡度修正对本库影响可忽略（中位 0.2 个百分点）。
但样本最大爬升只有 93 m，所以这条量化**不能外推到山区跑**——真实长坡上 GAP 会显著改变
解耦读数，届时需要先做高度通道平滑（活动 88 说明原始高度噪声本身会产生 26 个百分点的假信号）。
暂不引入 GAP 的决定记在这里，而不是留在「未量化」的挂账里。

前导窗口那一条特别值得记：**它不是「约定差异无所谓」**。起始段带伪影时
zeropad 会把伪影以 1/30 权重拉进平均（活动 151：起始 1422 W，zeropad 比 skip 高 2.2%），
而这正是 NP 那道 30 秒平均要防的东西。选 skip 不只是「随便挑一个」。

## 做这类工作的检查清单

新增或修改一个算法时：

- [ ] 公式进 `goldenlib.py`，只有一份；docstring 写清出处那一句
- [ ] 在 `test_golden_refs.py` 里加一条**解析真值**（能写出闭式解就用闭式解）
- [ ] 如果实现里有「定义没写死的选择」，在 goldenlib 里做成显式参数，并量出差值
- [ ] dump 测试调用生产函数，不重拼算式
- [ ] 与 Go 的偏离写进上表，附实测数字
- [ ] 变异检验：把实现改坏，确认**对照台和 ref-test 各至少有一条红**

最后一条是这套体系的自检：**如果一个 bug 能让两边同时变坏而检查不响，说明检查本身是装饰。**

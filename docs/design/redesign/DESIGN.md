## 1. 现状诊断（对着代码与截图，不是审美偏好）

现有 token 在 `web/src/index.css` 的 `@theme` 里，注释写着「由 ui-ux-pro-max 生成（Data-Dense
Dashboard）」。我用同一套查询重跑了一次设计系统生成，返回的正是同一组色值
（`#1E40AF` / `#3B82F6` / `#D97706`）——**所以问题不在配色选错，而在这套默认值没有回答
「这是给一个跑者每天看的个人工具」**。具体七条：

| # | 问题 | 证据 |
|---|---|---|
| 1 | **卡片汤**：每个信息块都是同权重 `border + rounded` 盒子，页面没有视觉落点 | 概览页 4 张目标卡 + 4 张统计卡 + 3 张大卡，边框粗细/圆角/内边距完全一致 |
| 2 | **琥珀色被同时当作品牌色、进度条色、热力图色、大数字色**，于是等于没有重点 | `--color-accent: #d97706` 同时用于 `ring`、目标进度、日历热力图、`180 km` 大数字 |
| 3 | **PMC 图 6 条线靠色相区分，图例还离得远**；红色过劳带几乎看不见 | 趋势页图例在顶部居中，`SB<-40` 的红区在深色底上不可辨；skill 规则明确要求「线型 + 直接标名，不能只靠色相」 |
| 4 | **死白**：概览右栏在档案卡下方空一大块；轨迹墙底部约 1/3 视口空着；汇总卡指标网格与柱图之间有空带 | 见 `shots/before-*.png` |
| 5 | **层级扁平**：页面标题（20px 级）与卡片标题几乎同大小，扫一眼分不出主次 | `训练趋势（PMC）` vs `表现预测（Banister 模型）` 尺寸差 <2px |
| 6 | **导航无图标，工具区 5 个同权重方框**，齿轮是纯图标 | `App.tsx` 的 `navItems` 只有文字；`中 / km / 暗 / ⚙ / 登出` 视觉权重相同 |
| 7 | **信息密度不均**：汇总页 12px 标签 + 大内边距，一屏只放得下 4 个月 | 汇总页每张月卡 8 项指标占满一整屏 |

## 2. 方向：把「仪表盘」改成「训练台」

一句话：**中性色占场，一个信号色只干一件事，层级靠留白和细线而不是盒子，图表自己会说话。**

三条硬规则：

1. **90% 的像素是中性色。** 面板只有一层，内部用 hairline + 16px 留白 + 大写 label 分层；
   只有可点元素（按钮 / chip / 输入 / 分段控件）才带边框或底色。
2. **信号色 `--flare` 只出现在「此刻最该看的数」和跑步数据上。** 品牌交互色 `--brand` 另开一支，
   两者不再混用。TSB 这类有语义的量用状态色（好/注意/坏），不跟着品牌色走。
3. **图表不靠颜色单独编码。** 线名直接标在右端、计划/预期用虚线而非新颜色、日负荷降成中性柱，
   每张图配一句文字摘要（读屏与色觉障碍用户也能拿到结论）。

## 3. 令牌

### 3.1 墨色层（dark）

| Token | 值 | 用途 | 对 `--panel` 对比度 |
|---|---|---|---|
| `--bg` | `#0A0D12` | 页面底 | — |
| `--panel` | `#10151D` | 面板 | — |
| `--panel-2` | `#161D27` | 抬起 / 悬停 / 热力图 0 级 | — |
| `--hair` | `#1E2733` | 细线 | — |
| `--hair-2` | `#2C3746` | 强细线 / 零线 | — |
| `--tx` | `#E9EEF6` | 正文 | 15.4:1 |
| `--tx2` | `#93A1B4` | 次要 | **6.9:1 ✓** |
| `--tx3` | `#5F6E82` | 装饰 / 分隔，**不承载信息** | 3.5:1 ✗（只用于大字与图标） |

### 3.2 语义色

| Token | dark | light | 用途 |
|---|---|---|---|
| `--brand` | `#4C6FFF` | `#3A5CE0` | 交互图形：选中、链接、焦点 |
| `--brand-tx` | `#7C97FF` | `#3350CC` | 同上但**文字安全**（6.6:1 / 6.5:1） |
| `--flare` | `#FF6B35` | `#DE551F` | 信号：此刻最该看的数 + 跑步 |
| `--good` / `--warn` / `--bad` | `#2FD3A5` / `#F5B942` / `#FF5A5F` | `#0E9C74` / `#96660A` / `#D22B31` | 状态 |
| `--ctl` / `--atl` / `--tsb` | `#4C6FFF` / `#FF6B35` / `#2FD3A5` | 同结构 | PMC 三条线 |
| `--load` | `#3A4A63` | `#B9C6DA` | 日负荷柱（中性，故意不抢线） |
| `--bike` | `#7AA2FF` | `#3A5CE0` | 骑行 |

> `--brand` 直接当文字用只有 4.3:1，所以另开 `--brand-tx`。这类「同一支色，图形一个值、
> 文字一个值」的拆法，是深色主题最常翻车的地方。

### 3.3 版式

沿用现有系统栈（**无外部字体，离线可用**，见 `index.css` 的 Round 8 约束）：
`--sans: Fira Sans / PingFang SC / Noto Sans SC …`，`--mono: Fira Code …`。

模数刻度：`40 / 26 / 20 / 16 / 14 / 12.5 / 11`。
所有数字走 `--mono` + `font-variant-numeric: tabular-nums`，纵向对齐不打架。
`11px` 只用于大写 + 字距的 label，正文最小 `14px`。

### 3.4 栅格与密度

左侧导航 236px + 12 列内容栅格，`gap: 14px`，面板内边距 `16px 18px`。
断点：`1180`（右栏下沉）/ `860`（导航转横向条、单列）。390px 实测**零横向溢出**。

## 4. 每页改了什么

### 活动 `/`（首屏）

**模块集合与现状完全一致**，只重排布局、去掉卡片汤：目标三档 / 连续记录 / 年总览 / 训练日历 /
档案 / 个人最佳 / 足迹地图 / 月历 / 活动列表（含年份 + 距离筛选、100 条一页分页）。

| 现状 | 新版 | 为什么 |
|---|---|---|
| 年度 / 月度 / 周目标 = 三张等大卡 | **一个「跑量目标」面板内三栏**，栏间 hairline 分隔 | 三者是同一件事的三个粒度，拆成三个盒子反而看不出是一组 |
| 连续记录卡（日期点 + 最长） | 保留，数字提到 40px，日期点做成带星期表头的小圆点 | 这是全页唯一「一眼看状态」的东西，值得最大字号 |
| 年总览 = 四张统计卡 | **一条横向读数带**，右侧挂「导出分享图」与跑步/骑行拆分 | 四个数不需要四个盒子 |
| 训练日历 + 右侧档案卡（下方大片死白） | 训练日历 8 栏 + 档案 4 栏，**档案卡补满四格读数** | 死白来自右栏比左栏矮 |
| 个人最佳 / 足迹地图 / 月历 散在不同高度 | **三块同排**（各 4 栏） | 三者都是「回看」类信息，同排便于横向扫 |
| 活动列表卡片 | **一行一条**：日期｜距离｜配速｜时长｜心率｜爬升 | 表格式扫读比卡片快得多 |

> 我原本在首屏加了「今天 TSB + 行动建议」和「月度跑量」条，按你的决定**已撤掉** ——
> 首屏内容保持现状，TSB 仍归趋势页。

### 趋势 `/trends`
- PMC 拆成**上下两块共 x 轴**：上线图（CTL 面积 + ATL 虚线 + TSB 实线，线名直接标在右端并带当前值），
  下线日负荷中性柱。过劳区画成有文字的带（`过劳区 TSB < −30`），不再是一块看不见的红。
- 右侧「怎么读」栏：三个读数 + **一段人话结论**（11 月连投三场后 ATL 顶在 60 以上…）。
- 表现预测：纵轴向下 = 更快，每个点标日期；预测表里全马标 ⚠ 不可靠（外推比例 > 1）。
- 成绩格式修 bug 级问题：半马/全马要写成 `1:39:26` / `4:15:39`，不是 `99:26` / `255:39`。

### 轨迹墙 `/map`
- 左栏放大到 3/12 并 sticky，统计 + **全部轨迹叠加图**（选中路线高亮）；
  现有版本地图缩略图只有 ~170px 高，而底部 1/3 视口空着。
- 墙用 `auto-fill minmax(116px)` 铺满，内部滚动，`×N` 徽标 + 悬停显示 km/配速。
- 生产实现仍走 MapLibre，只是把面板尺寸和层级换掉。

### 汇总 `/stats`
- 卡片改**行式**：`周期｜距离｜次数·时间｜均配速｜爬升｜每日 sparkline`，一屏从 4 个周期变 10 个；
  当月用左侧 flare 指示条高亮。爬升用真实月度汇总，不是估算。

### 赛事 `/races`
- 只换视觉骨架（表格 + 状态 chip），信息架构不动。

## 5. 落地路线（如果要接进 React）

改动集中在**令牌与外壳**，业务组件基本只动 className：

1. **第 1 步（半天，收益最大）**：改 `web/src/index.css` 的 `@theme` 为 §3 的令牌，
   补 `--brand-tx` / `--load` / `--ctl/atl/tsb`；`html[data-theme="light"]` 同步。
   Tailwind v4 的 `@theme` 变量一改，`bg-card` / `text-muted-foreground` 全站跟随。
2. **第 2 步**：`App.tsx` 顶栏 → 左侧 rail（6 项 + 图标 + `aria-current`），
   工具区降权（图标按钮 + `aria-label`，登出移出主视觉）。
3. **第 3 步**：面板降级为「一层 + hairline」：删掉嵌套边框，统一 `--r-l` 圆角与 16px 内边距。
4. **第 4 步**：PMC 图（`Trends.tsx` + ECharts option）按 §4 重画：
   `grid` 拆两层、`legend` 关掉改用 `series.endLabel`、日负荷改 `bar` + 中性色、
   过劳带用 `markArea` + `label`。ECharts 6 原生支持 `endLabel`，不用换库。
5. **测试**：`web/e2e/smoke.spec.ts` 里按文字定位的断言（导航、卡片标题）要跟着改；
   `make e2e` 是最终验收。

**不动的东西**：信息架构与路由、`glossary.ts` 术语表、`docs/ALGORITHMS.md` 口径、i18n key、
后端 API。这次只碰「怎么看」，不碰「算什么」。
